# SPRINT_01.md — Fundación WiseLife

**Propósito:** planificación específica del Sprint 1.
**Responsable:** Scrum Master. **Estado:** Requiere validación del equipo.

## Objetivo
Dejar validada la base de acceso, perfiles, arquitectura de datos y criterios de seguridad necesarios para iniciar el MVP sin comprometer información clínica.

## Alcance propuesto
- Refinar historias P0 de identidad, paciente y profesional.
- Validar Supabase Auth, perfiles, roles y RLS contra el esquema vivo.
- Definir contratos de onboarding y disponibilidad.
- Preparar criterios QA para navegación, auth, permisos y persistencia.
- Confirmar preview, build y checks mínimos de CI/CD.

## Fuera de alcance
Implementar pagos, IA, videollamada, chat, migraciones productivas o cambios de negocio no refinados.

## Definition of Ready
Historia con criterios verificables, dependencias, diseño, estados, permisos, riesgos y prueba conocida.

## Definition of Done
Criterios aceptados, pruebas funcionales/negativas, accesibilidad, revisión de seguridad, documentación y trazabilidad en changelog.

## Riesgos y bloqueos `[POR DEFINIR]`
Capacidad del equipo, duración del sprint, responsables individuales y criterios de salida — **Responsable:** Scrum Master + Product Owner.
